# ROMX Metadata 0.1.0

Metadata is an optional UTF-8 JSON object embedded in the ROMX container. It is located by the footer and never by an external path. The normative field constraints are in `schema/romx-metadata.schema.json`.

ROMX uses `name` as the canonical display name because the frontend keeps game records in its own database rather than in a RetroArch playlist. A RetroArch adapter maps `name` to the database `name` field and the frontend display label.

## Required fields

| Field | Type | Meaning |
|---|---|---|
| `schema_version` | string | Must be `0.1.0` |
| `name` | string | Canonical game display name |
| `platform` | string | Platform ID from `PLATFORMS.md` |
| `payload_format` | string | Extracted ROM format, without a leading dot |
| `crc32` | string | Effective database lookup CRC32, lowercase eight-digit hexadecimal |

`crc32` is a lookup aid, not a payload integrity claim. Writers regenerate it from the payload by default. An explicit override is allowed only when a caller intentionally wants to match a published database identity. `origin_crc32` is independent and optional; when present, it is the CRC32 calculated from the exact payload bytes. It is not generated by default and is never replaced by an override.

CRC32 is RetroArch-compatible CRC-32/ISO-HDLC: polynomial `0x04C11DB7`
(reflected `0xEDB88320`), initial value `0xFFFFFFFF`, reflected input/output,
and final XOR `0xFFFFFFFF`. It is serialized as exactly eight lower-case
hexadecimal characters without a prefix; `123456789` produces `cbf43926`.

## Optional fields

### Database-compatible game information

| Field | Type | Meaning |
|---|---|---|
| `serial` | string | Cartridge, release, or disc serial |
| `developer` | string | Developer |
| `publisher` | string | Publisher |
| `origin` | string | Country or region of development/origin |
| `franchise` | string | Franchise or series name |
| `release_date` | string | `YYYY`, `YYYY-MM`, or `YYYY-MM-DD` |
| `genre` | string[] | Genre labels; adapters may combine them for a scalar database field |
| `region` | string[] | Release regions; adapters may combine them for a scalar database field |
| `language` | string | Language information in the database-compatible form |
| `users` | integer | Maximum supported users/players |
| `coop` | boolean | Cooperative play is supported |
| `rumble` | boolean | Rumble is supported |
| `analog` | boolean | Analog input is supported |
| `enhancement_hw` | string | Required or supported enhancement hardware |
| `category` | string | Content category |
| `media` | string | Original media type |
| `description` | string | Plain-text description |

The RetroArch adapter maps `release_date` to its `releaseyear` and `releasemonth` fields, and `users` to `users`. ROMX keeps the date and collection shapes readable instead of copying RetroArch's internal field spelling. The `platform` value selects the frontend's database; it is not a per-game database field.

### ROM provenance and embedded cover

| Field | Type | Meaning |
|---|---|---|
| `origin_crc32` | string | Optional CRC32 calculated from the exact ROM payload |
| `dump_status` | string | Optional provenance/status hint for the source dump |
| `cover` | object | Optional descriptive information about the embedded cover; not an integrity record |
| `cover.mime_type` | string | Optional; if present, must be `image/png` |
| `cover.width` / `height` | integer | Optional pixel dimensions |

`dump_status` describes provenance, not cryptographic integrity or launchability. `good` can indicate a known-good dump; `bad`, `overdump`, `hack`, `translation`, and `homebrew` describe known variants or conditions. It must not be used as a replacement for the footer SHA-256 or as an automatic rejection rule. It is retained for discussion because it has no direct RetroArch database equivalent.

The `cover` object is descriptive only and has a closed schema. It may contain
only `mime_type` (`"image/png"`), `width` (integer 1–8192), and `height`
(integer 1–8192); `additionalProperties` is false. It is not a filesystem path,
URL, command, credential, or checksum. The frontend should display the embedded
cover first; a database thumbnail is a fallback or user-selected replacement.
Cover bytes themselves follow the PNG profile in `ROMX-SPEC.md`. `origin_crc32`,
when enabled, must likewise be calculated from the exact payload bytes.

Metadata JSON is strict UTF-8 without a BOM and follows RFC 8259. Duplicate
member names are forbidden in every object, including nested objects; a parser
must not apply “last key wins” behavior. Escaped unpaired UTF-16 surrogates are
also invalid; a valid surrogate pair is accepted as one Unicode scalar.


## RetroArch interoperability map

The table maps every standard ROMX metadata field to the corresponding RetroArch database (`.rdb`) key and JSON playlist (`.lpl`) key. A dash means that the target has no native structured field. Indirect mappings are called out in the notes. Database key names follow RetroArch's RDB reader; playlist key names follow the JSON playlist format described in the [RetroArch playlist documentation](https://docs.libretro.com/guides/roms-playlists-thumbnails/).

| ROMX field | RetroArch database | RetroArch playlist | Mapping and notes |
|---|---|---|---|
| `schema_version` | — | — | ROMX format field |
| `name` | `name` | `label` | Canonical game name and display title |
| `platform` | Database/system name | `db_name` | Selects the system database/playlist; not a per-game RDB record field |
| `payload_format` | — | `path` (extension/member) | Determines the output content extension or archive member; it is not a standalone playlist metadata key |
| `crc32` | `crc` | `crc32` | Effective lookup value; playlist form is `XXXXXXXX\|crc` |
| `origin_crc32` | — | — | Optional payload provenance; never a lookup key |
| `serial` | `serial` | `crc32` | Playlist `crc32` can carry a serial token when the system uses serial matching |
| `developer` | `developer` | — | Database information |
| `publisher` | `publisher` | — | Database information |
| `origin` | `origin` | — | Development/origin country or region |
| `franchise` | `franchise` | — | Series/franchise name |
| `release_date` | `releaseyear`, `releasemonth` | — | ROMX ISO date is split by the adapter; current RetroArch metadata does not require a playlist field |
| `genre` | `genre` | — | ROMX array may be combined for the scalar RDB value |
| `region` | `region` | — | ROMX array may be combined for the scalar RDB value |
| `language` | `language` | — | Database language information |
| `users` | `users` | — | Maximum supported users/players |
| `coop` | `coop` | — | Cooperative-play capability |
| `rumble` | `rumble` | — | Rumble capability |
| `analog` | `analog` | — | Analog-input capability |
| `enhancement_hw` | `enhancement_hw` | — | Enhancement hardware |
| `category` | `category` | — | Database category |
| `media` | `media` | — | Original media type |
| `description` | `description` | — | Database description |
| `dump_status` | — | — | ROMX provenance hint; not a RetroArch lookup or playlist field |
| `cover` | — | `label` (indirect) | Cover bytes are embedded in ROMX; a generated RetroArch thumbnail filename is derived from the playlist label |
| `cover.mime_type` | — | — | Embedded cover descriptor |
| `cover.width` / `height` | — | — | Embedded cover descriptor |

RetroArch's database uses `crc` and `name` inside RDB records, while a playlist uses `crc32` and `label`. The database is selected by `db_name`; thumbnails are then associated primarily through the resulting game name and playlist/system directory, not through the CRC itself. RetroArch documents CRC/serial as matching keys and database `name` as the assigned game name. See the [RetroArch database guide](https://docs.libretro.com/guides/databases/) and the [database reader](https://raw.githubusercontent.com/libretro/RetroArch/master/database_info.c).


## LPL conversion boundary

ROMX metadata has no LPL-only extension namespace. `path`, `core_path`, `core_name`, `db_name`, playlist settings, and playback state are conversion inputs or outputs, not portable ROMX fields. An LPL converter derives them transiently from `platform`, `payload_format`, `name`, `crc32`, and its output options. Filesystem paths and frontend runtime state are never embedded in ROMX metadata.
