# ROMX 0.2.0 开发政策

**状态：正在开发，尚未冻结。** 本文约束 `main` 上 ROMX 0.2.0 标准的修改。

## 仅限容器的范围

ROMX 标准化序列化字节、注册表、验证、故障隔离，以及可变数据的提交与失败隔离语义。
Library API、VFS adapter、临时文件、数据库或网络访问、模拟器选择、用户界面和主机
存档目录策略不属于本标准。

只有当一个功能的字节表示、验证和恢复行为能够脱离特定前端、library、模拟器与
操作系统独立定义时，它才属于容器标准。

## 实现审查

每条规范性规则都必须存在实际可行的实现路径。审查至少必须能够说明：

- 使用经过检查的整数运算进行有界解析；
- 通过流式或随机读取工作，不把完整 payload 放入内存；
- 保证 entrypoint 的原生第一个字节位于文件绝对偏移零；
- 确定性的验证与故障隔离；
- 通过有界写入更新 mutable 数据，不复制 immutable payload；
- 严格区分有效容器解析与未验证的 salvage；
- 明确处理未知注册值。

实现路径只用于证明规则可实现，不会使某个具体实现成为规范的一部分。

## 版本边界

ROMX 0.2.0 使用 footer wire version `2` 和 metadata schema version `0.2.0`。
Reader 必须先验证 wire version，再解释 footer 或任何区域。

由于格式尚未冻结，对字节语义、字段语义或有效性规则的不兼容修改可能需要分配新的
wire version。未知 wire version 不得按版本 `2` 解释。

只有项目明确冻结 0.2.0 规范并发布对应的一致性夹具后，稳定兼容承诺才开始生效。
